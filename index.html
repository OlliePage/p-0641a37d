Statuses, the formula, and how to update it

Status vocabulary

Area completion is the weighted mean of its nodes' percentages, sizes S = 1, M = 2, L = 3, out nodes excluded. Colour never stands alone: every mark carries its glyph and word.

The contract

  1. Claim before you build. python3 tools/roadmap/claim.py <node-id> "what you are doing" marks the node active with your branch and rebuilds the page. Hooks refuse edits to code on a branch with no claim.
  2. Release when the evidence moves. claim.py <node-id> --release branch|merged|live --evidence <path>. A merge is refused while a claim is still active; a push is refused when work changed but the graph did not.
  3. Commit the graph and both built pages with the work. Roadmap-only updates go straight to main with tools/roadmap/push_roadmap_to_main.sh. Installed Git hooks check pushed commits; Claude hooks add session checks. There is no hosted CI.
python3 tools/roadmap/claim.py --list ready
python3 tools/roadmap/claim.py <node-id> "what you are doing"
python3 tools/roadmap/claim.py <node-id> --release branch --evidence <path>
python3 tools/roadmap/git_hooks.py install
bash tools/roadmap/publish_pages.sh

Move to merged after the actual merge, and live after deployment/device proof. The weighted percentage is not a release forecast. Published source commit.
